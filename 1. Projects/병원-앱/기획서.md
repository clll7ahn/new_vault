# 병원 앱 기획서

## 프로젝트 개요

### 목적
중소규모 병원(의사 5~30명)이 디지털 채널을 통해 환자와 효과적으로 소통하고, 예약·진료 업무를 효율화할 수 있도록 지원하는 모바일 앱과 웹 기반 관리 시스템을 구축한다.

### 대상 병원 규모
- 의사 5~30명 규모의 중소형 의원·병원
- 대면 진료 중심 운영 (비대면 진료 제외)
- 별도 IT 담당자 없이 원무과 수준에서 운영 가능한 시스템

### 핵심 가치
| 가치 | 설명 |
|---|---|
| 편의성 | 환자가 언제 어디서나 예약 확인·변경 가능 |
| 신뢰 | 검증된 의료진 정보와 진료 기록 제공 |
| 효율 | 전화 예약 감소, 원무 업무 부담 절감 |
| 소통 | 병원-환자 간 메시지 및 알림으로 관계 강화 |

---

## 타겟 사용자

### 환자 (Flutter Mobile App)
- **주 사용자**: 스마트폰을 사용하는 20~60대 외래 환자
- **특성**: 예약 편의성과 대기 시간 최소화를 원함
- **니즈**: 진료 기록·처방 정보 손쉬운 조회, 병원 공지 수신

### 병원 관리자 / 원무 담당자 (Web 관리 페이지)
- **주 사용자**: 원무과 직원, 병원장, 간호사
- **특성**: IT 비전문가이며 직관적 UI 필요
- **니즈**: 예약 현황 한눈에 파악, 환자 연락·메시지 관리

### 의료진 (Web 관리 페이지 일부 기능)
- **주 사용자**: 담당 의사, 간호사
- **특성**: 진료 중 빠른 조회 필요
- **니즈**: 오늘의 예약 환자 목록, 환자 메시지 확인

## 기능 목록

### 환자 앱 (Flutter Mobile)

#### 1. 병원 정보
- 병원 소개(위치, 전화번호, 주차 안내)
- 진료 시간표 (요일별, 공휴일 안내)
- 진료과 목록 및 상세 설명
- 의료진 프로필 (사진, 전문 분야, 약력)
- 지도 연동 및 길찾기 링크

#### 2. 예약 / 접수
- 진료과·의사·날짜·시간 선택 예약
- 예약 내역 확인 (예정 / 완료 / 취소)
- 예약 변경 및 취소
- 방문 전 사전 문진표 입력 (선택)
- 대기 순번 실시간 확인 (선택, Phase 2)

#### 3. 소통
- 의료진·원무과로부터 메시지 수신
- 1:1 문의 메시지 전송
- 푸시 알림 (예약 확인, 진료 준비, 결과 안내)

#### 4. 진료 기록
- 최근 진료 내역 목록 (날짜, 진료과, 담당의)
- 진료 상세 요약 (의사 메모 공개 범위 내)
- 검사 결과 조회 (혈액검사, 영상 등 병원 제공분)

#### 5. 처방 / 투약 정보
- 처방 내역 조회 (약품명, 복용법, 기간)
- 복약 알림 설정

#### 6. 건강 정보 콘텐츠
- 병원 공지사항
- 건강 팁 / 질환 정보 게시글
- 계절·이슈별 건강 캠페인 배너

---

### 관리 페이지 (Web)

#### 1. 대시보드
- 오늘의 예약 현황 (시간대별 예약 수, 취소 수)
- 미확인 메시지 알림
- 주간·월간 예약 통계 요약
- 빠른 액션 버튼 (예약 등록, 환자 검색)

#### 2. 환자 관리
- 환자 목록 검색·조회 (이름, 생년월일, 전화번호)
- 환자 상세 정보 (기본 정보, 방문 이력, 메시지 이력)
- 환자 등록 / 수정

#### 3. 예약 / 스케줄 관리
- 캘린더 뷰로 예약 현황 확인
- 예약 수동 등록·변경·취소
- 의사별 일정 블록 설정 (휴가, 외부 일정)
- 예약 가능 슬롯 설정 (시간 간격, 최대 인원)

#### 4. 의료진 관리
- 의료진 프로필 등록·수정·비활성화
- 진료 가능 요일·시간 설정
- 진료과 배정

#### 5. 메시지 / 알림 관리
- 환자 1:1 메시지 수신 및 답변
- 단체 푸시 알림 발송 (대상 필터링 포함)
- 자동 알림 규칙 설정 (예약 D-1 리마인더 등)

#### 6. 콘텐츠 관리
- 공지사항 작성·수정·삭제
- 건강 정보 게시글 관리
- 배너 이미지 등록 및 노출 기간 설정

#### 7. 통계 / 리포트
- 기간별 예약 수·취소율 차트
- 진료과·의사별 방문 환자 수
- 앱 가입자 수, 활성 사용자 추이
- CSV 다운로드

## 사용자 스토리 (핵심)

1. **환자 예약**
   As a 환자, I want 앱에서 원하는 의사와 날짜를 선택해 예약하고 싶다 so that 전화 연결 없이 편리하게 진료를 예약할 수 있다.

2. **예약 확인·취소**
   As a 환자, I want 내 예약 목록을 보고 불필요한 예약을 취소하고 싶다 so that 병원 방문 없이도 일정을 조정할 수 있다.

3. **진료 기록 조회**
   As a 환자, I want 이전 진료 내역과 검사 결과를 앱에서 조회하고 싶다 so that 다른 병원 방문 시 참고 자료로 활용할 수 있다.

4. **처방 복약 알림**
   As a 환자, I want 복약 알림을 설정하고 싶다 so that 약을 빠뜨리지 않고 제때 복용할 수 있다.

5. **병원 공지 수신**
   As a 환자, I want 병원 공지와 건강 정보를 앱 알림으로 받고 싶다 so that 병원 소식을 놓치지 않을 수 있다.

6. **예약 현황 관리 (관리자)**
   As a 원무 담당자, I want 오늘의 예약 목록을 한눈에 보고 싶다 so that 당일 진료 흐름을 빠르게 파악하고 대응할 수 있다.

7. **단체 알림 발송 (관리자)**
   As a 병원 관리자, I want 특정 조건의 환자에게 단체 메시지를 보내고 싶다 so that 독감 예방 접종 같은 캠페인 안내를 효율적으로 전달할 수 있다.

8. **의료진 스케줄 설정 (관리자)**
   As a 원무 담당자, I want 의사별 진료 가능 시간과 휴무를 설정하고 싶다 so that 환자가 예약 가능한 슬롯만 선택할 수 있도록 관리할 수 있다.

## MVP (Phase 1) 범위

**목표**: 예약 흐름을 디지털화하여 전화 예약 의존도를 낮춘다.

### 포함 기능
- **앱**: A-01~A-13, A-22 (온보딩, 병원 정보, 예약 전 과정, 내 정보)
- **관리 페이지**: W-01, W-02, W-03~W-06, W-07~W-08 (로그인, 대시보드, 예약·환자 기본 관리)

### 제외 기능 (Phase 2~3에서 추가)
- 메시지·알림, 진료 기록, 처방 정보, 건강 콘텐츠, 통계

### 성공 기준
- 앱 예약 전환율 30% 이상 (3개월 내)
- 예약 오류·중복 건수 0건 유지
- 관리자 온보딩 1시간 이내 완료

## 비기능 요구사항

### 보안 및 개인정보보호
- **개인정보보호법** 준수: 최소 수집, 목적 외 이용 금지, 수집·이용 동의
- **의료법** 준수: 진료 기록 열람·제공 범위 명확화
- 전송 구간 TLS 1.2 이상 암호화
- 서버 측 개인정보 및 진료 정보 암호화 저장 (AES-256)
- 관리 페이지 역할 기반 접근 제어(RBAC): 관리자 / 의료진 / 원무 구분
- 세션 만료 및 자동 로그아웃 (비활성 15분)
- 개인정보 처리방침 및 이용약관 앱 내 제공

### 성능
- 앱 최초 로딩(콜드 스타트) 3초 이내
- 예약 완료 API 응답 2초 이내 (p95)
- 동시 접속 200명 이상 지원 (중소병원 기준)
- 이미지 레이지 로딩 및 CDN 활용

### 접근성
- WCAG 2.1 AA 수준 준수 (관리 페이지 웹)
- 앱 텍스트 크기 조절 지원 (시스템 폰트 크기 반영)
- 고대비 모드 고려 (어르신 사용자 비중 고려)
- 터치 타겟 최소 44×44pt 이상

### 가용성 및 유지보수
- 서비스 가동률 99.5% 이상 (월 기준)
- 정기 점검은 새벽 2~4시 진행, 사전 공지
- 앱 강제 업데이트 없이 최소 2개 이전 버전 지원
- 오류 로그 모니터링 및 알림 체계 구축
